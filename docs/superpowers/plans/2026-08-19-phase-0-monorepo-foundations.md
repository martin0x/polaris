# Phase 0 — Monorepo Foundations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restructure Polaris into Bun workspaces (`apps/web`, `packages/core`, `packages/backend`) with zero behavior change: the deployed app is byte-for-byte the same product, all tests stay green, and the Convex dev loop works.

**Architecture:** The existing Next.js app moves wholesale to `apps/web` (git mv, no code changes). The eight framework-free modules (dates, stats, money, months, format, tasks, parser, highlight) move to a new `@polaris/core` package consumed as TypeScript source via `transpilePackages`. A new `@polaris/backend` package scaffolds the Convex project (empty schema + a `ping` query) with a `convex-test` smoke test, wired to dev and prod deployments.

**Tech Stack:** Bun 1.3.14 (package manager/workspaces/script runner — NOT runtime), Next.js 16.2.4, Convex (latest 1.x), convex-test, Vitest 4.1.5, Prisma 7 (unchanged), Vercel.

**Spec:** `docs/replatform.md` (§02 target architecture, §03 Bun policy, §05 "Phase 0 — Monorepo foundations")

## Global Constraints

Copied from the spec and repo instructions — every task's requirements implicitly include these:

- **Zero behavior change.** Phase 0 exit: "the deployed app is byte-for-byte the same product; tests green; Convex dev loop works" (spec §05). No source logic changes — only file moves, import-specifier rewrites, and config.
- **Bun as toolchain only.** "Bun as package manager, workspace tool, script runner, and `bunx` for every CLI (convex, expo, next) … it stays the single lockfile across all workspaces" (spec §03). Never `bun test` (that's Bun's runtime test runner) — always `bun run test` (Vitest). `next dev`/`next build` run on Node, never the Bun runtime.
- **Browser-coupled libs stay in the web app:** `sounds`, `sort-preference`, `syncQueue` (spec Phase 0). Also `src/lib/utils.ts` — not in the spec's move list; it stays.
- **Next.js 16.2.4 is not the Next you know** (AGENTS.md). Consult `node_modules/next/dist/docs/` before touching Next-related config. Relevant facts already verified there for this plan: root detection uses `bun.lock` (`…/01-next-config-js/turbopack.md`), `transpilePackages` transpiles workspace TS packages (`…/transpilePackages.md`), `outputFileTracingRoot` is required for monorepo tracing (`…/output.md`).
- **No UI changes.** The only edits to `.tsx` files are import-specifier lines. If any task somehow requires more than that, stop and read `docs/design/README.md` + `docs/design/polaris-design-system.md` first (CLAUDE.md rule).
- **No CI exists** — verified: there is no `.github/`, GitLab, or Circle config in the repo. The spec's "CI … updated" is a no-op. Do NOT invent a CI pipeline in this phase (YAGNI).
- **Workspace names:** root `polaris`, app `@polaris/web`, packages `@polaris/core`, `@polaris/backend` (later phases add `@polaris/tokens`, mobile). The root `test` script filters on `@polaris/*`, so these names are load-bearing.
- **Baseline numbers** (measured 2026-08-19 on `main`-equivalent tree, all green): unit suite = 19 files / 146 tests; the 8 moving modules carry 8 test files / 76 tests (so post-split: web 11 files / 70 tests, core 8 files / 76 tests); integration suite = 18 files (Docker Postgres required).
